# 智能推荐：独立模块

2026-11-06 实现版。日常练习与智能推荐为两个独立入口，VP 房间由另一模块维护。

## 业务边界

共享 CF 官方题库缓存、公开题面／题解／参考代码、已同步提交。智能推荐有自己的难度设置、候选池、偏好、任务和推荐快照。不读取或修改日常练习的动态参考水平、训练中状态、冷却或反馈。

默认区间为当前 CF Rating ±200，没有 Rating 时参考 1800；可选手动上下限、是否包含以前尝试但未 AC 的题。排除已知 AC、评测中的题、区间外题和未评级题。历史完成情况仅覆盖已同步记录。

本轮按用户明确偏好推荐，尚未把经验库和近期训练画像送入检索。也没有实现开始、换题、AC 核对或智能推荐自身的动态 Rating；不能借用日常训练接口来补这些状态。

## 正式流程

### 推荐策略（工作流 v7）

用户接受不够准确的尝试题。普通偏好中的程度和侧重点用于排序，不拆成必须全部满足的条件；只有明确的方向、排除与用户范围继续约束候选。审查记录匹配程度和证据，不以 moderate/weak/unknown 阻止最终比较。只要有已送审候选，最终必须给出至少一个首选；部分匹配或依据有限时使用固定的诚实提示，不宣称完全满足偏好，也不暴露解法。`qualifiedCount` 仍只统计证据充分的核心匹配数，不等于允许推荐的题数。

模型若给出格式有效但空的首选集合，程序按已有匹配评估、缓存、难度距离和题号选择尝试题，并明确标记未得到 AI 首选。没有可送审候选时才返回空结果；调用或引用格式失败仍报错，不伪造成功。提示词与工作流升级会使旧的无推荐快照失效。

### 题面内容分支

当 `retrievalTarget=statement`，走独立的全文召回流程，不经过下述基础池优先和 64 题预筛：

1. AI 根据当次需求给出 1～6 组中英文查询，包含直接表达、别名和有把握的关联实体。关联项只增加召回入口，不增加用户必须满足的条件；不指定题号，也不为每题生成关键词卡。
2. 按用户难度、AC、尝试题和明确方向筛出可用题面。对全部原始题面按约 400 token、重叠 50 token 分块，保留原文字符位置。每块至少 80 个非空白字符，并包含文字或数字；纯符号不索引。不足 64 token 或未达到字符下限的尾块合并或向前扩充上下文，合并最多 480 token，给模型前缀留空间。完整原文已覆盖时立即停止，不再生成重复尾块；整份资料仍不够最小长度则不作为题面检索块。关键词和本地向量独立检索全部有效文本块，向量不受 BM25 预筛限制。
3. 每个查询、每种方法、每道题取最相关片段，按题 RRF 融合，取前 16 题；每题保留至多 3 个匹配原文片段。题面后部也参与召回与审查，不受常规资料包前 12,000 字符限制。
4. 每批 8 题送 AI 核对，首批没有明确或部分匹配时再审第二批，然后比较所有已送审候选并给出尝试题。只发送题面证据及基础题目信息，不让题解和资料卡中的提及替代原文。此分支无需等待在线抓取题解。选题后资料卡收录仍沿用统一规则。
5. 向量按模型和原文哈希缓存，每 96 块落盘一次并更新进度。首次准备较慢，后续复用；不额外产生每题 LLM 分析费用。命中片段只属于本轮审查，不改变公共资料卡哈希。
6. 内部记录查询、全文题数、块数、各路命中及片段位置。发布与复用时检查全量可用题面版本；未审查题新增或更新也会使旧结果过期。公开结果只增加检索题数，不暴露查询扩展词、算法或解法。

### 解法、基础信息与混合需求

1. 用户点击生成，自动整理尚未准备或已过期的基础范围。保留原来的约 100 题基础池，但它不再限制推荐资格，也不限制后续资料卡总量。冻结用户输入签名，不自动重试付费调用。
2. 首先解释偏好：生成中英文检索查询、核心标准、软偏好、可选实现查询，以及受当前标签白名单约束的 `tagGroups` / `excludeTags`。组内 OR，组间 AND；没有明确算法方向则不筛标签，不把能力偏好或题目故事强行映射成标签。三个路由字段 `tagGroups`、`excludeTags`、`retrievalTarget` 必填，漏返时停止，不静默放宽。
3. 优先检索基础池及该用户已收录的扩展资料卡。按照当前难度、已 AC、尝试题开关和明确标签过滤。相关候选少于 8 道，或者首轮审查没有充分匹配，才触发池外检索。
4. 池外检索先筛标签，再按 `retrievalTarget` 选择资料：`solution` 主要查题解、题面及代码；`metadata` 主要查基础属性；`mixed` 混合原始资料。使用归档题面和实际缓存的题解，不由资料卡补造正文。BM25 最多保留 48 道关键词命中，再分散补足至多 64 道有对应资料的候选。关键词统计不把 statement、themed 等请求套话当作主题命中；中英文查询去重。这几个分支仍是有界召回，并非全库向量检索。
5. 本轮候选统一采用本地 multilingual-e5-small + BM25 排序。每个查询、每种方法、每道题只取权重调整后最相关的一段原始资料，再按题融合排名，不按资料通道数累加票数。所有新旧题使用相同规则，资料卡不提供额外排名分，不再给予缓存题固定加分。原文按约 400 token 分块、重叠 50 token；向量按模型与内容哈希复用。学习卡继续用于 AI 审查与知识复用，而非独立投票通道。
6. 选 Top 8，尝试补充其公开资料。整轮最多尝试 8 道，资料补充预算 180 秒（已发出的 HTTP 请求最多另需其超时时间）；访问受限立即停止后续抓取，保留已有资料继续审查。PDF 沿用文本提取，不能读取时保留缺失状态，不编造内容。
7. AI 按原始题面、题解、实际参考代码、元数据逐项评价，资料卡只作线索。基础信息足以支持明确要求时也可推荐；标签不能证明实现细节或正文场景。全部已送审题进入最终比较，匹配不足如实保留。首轮只有 weak/unknown 时继续第二批；尚未扩展则先扩展，已扩展也不能提前终止，总计最多 16 道。
8. 最后 AI 比较已评价的题，必须选出至少一道当前最值得尝试的题，允许并列。同档优先已有有效资料卡，再按难度距离和题号稳定选择。空首选采用上述程序兜底；不得由助手人工指定题号替换结果。
9. 选题后才给少量新题生成可复用资料卡，最多 20 道，每次调用最多 5 道。先完整资料，再部分资料，最后仅基础信息；本批完整题数决定缺资料配额（每 4 道完整题最多搭配 1 道缺资料题），不得借旧池凑比例。卡校验失败后重新核算 80%，未通过的卡只留失败缓存，不加入检索语料。
10. 发布前重查用户条件和审查过的材料哈希。新增有效卡及用户收录记录与推荐快照一起提交；被取消的任务保留原始资料，不发布结果。未入池题同样可以成为推荐，原始资料和向量缓存不删除。

每轮最多 9 次模型调用（意图、至多两轮审查、比较、至多四批卡）；相同条件重复请求复用快照，不调用模型。缓存充分且无需扩展时通常为 3 次。后台只运行一个推荐任务，与手动资料准备互斥。停止不保证已发出请求免费；重启标记中断，不自动恢复计费。

## 数据与缓存

- `smart_settings`：用户的独立难度与尝试题设置。
- `smart_preparations` / `smart_pool_entries`：题池输入签名、候选与储备及历史归属。
- `training_public_materials` / `training_editorial_attempts`：跨模块共享的公开资料与抓取尝试。
- `smart_public_cards`：公共卡，键包含资料包哈希、模型、卡片提示词和结构版本，不包含用户偏好。
- `smart_card_memberships`：用户长期收录的扩展资料卡题号；不受基础池 100 题容量限制。AC 或范围变化后不再参与当前检索，公共资料仍保留。
- `smart_jobs`：用户任务状态、偏好、进度、用量；没有密钥和私有源码。
- `smart_recommendations`：用户推荐快照、输入签名与内部诊断；诊断不通过推荐接口暴露。
- `.local/smart-vectors`：由模型文件哈希和具体索引内容决定的向量缓存。

相同条件重复生成会复用原快照；切回之前偏好且语料条件未变时也可恢复对应结果。包括池外候选在内的已审查资料变化、模型或提示词变化会使结果过期。只读状态接口不得触发网络抓取、生成或改动日常训练。

## 接口

所有接口要求当前本地账号登录，服务只绑定 127.0.0.1。

| 接口 | 作用 |
|---|---|
| GET `/api/intelligent/pool` | 候选、来源、资料状态，不含标签、题解正文 |
| POST `/api/intelligent/settings` | 独立难度、包含尝试题；运行中禁止修改 |
| POST `/api/intelligent/prepare` | 整理候选，不调用模型 |
| POST `/api/intelligent/sync` | 同步绑定 CF 账号最近最多 1000 次提交并整理 |
| GET/POST `/api/intelligent/editorials` | 资料准备状态／启动 |
| POST `/api/intelligent/editorials/cancel` | 停止资料准备 |
| GET `/api/intelligent/material?id=cf:…` | 当前用户候选或历史候选的原始资料 |
| GET `/api/intelligent/recommendation` | 独立设置、任务状态、当前保存的推荐 |
| POST `/api/intelligent/recommendation` | `{ "preference": "本次目标" }`，启动或复用 |
| POST `/api/intelligent/recommendation/cancel` | 停止；等待当前请求返回后结束 |

任务状态：idle → running → completed / failed / cancelled；停止中的请求显示 cancelling，重启后显示 interrupted。没有可送审候选时保存 problem 为 null；只有弱匹配时仍保存尝试题，`approximate=true`，并通过 `matchLevel` 保留实际评估等级。

### 排序与资料来源规则（工作流 v4）

| 检索目标 | 原始资料权重 |
|---|---|
| statement | 题面 1；其他资料不参与 |
| solution | 题解 1、题面/代码 0.85、基础信息 0.35 |
| metadata | 基础信息 1、题面/题解 0.8 |
| mixed | 题面/题解 1、代码 0.85、基础信息 0.5 |

权重用于选择该题最相关的证据，不累加来源票数。卡片有无与缓存成员身份不进入检索分数；只在 AI 已判定为同一首选档时，沿用缓存、难度距离、题号的稳定选择。排名分数不是匹配概率。缺少用户指定资料时可以扩展一次，仍无资料则保存无匹配结果，不拿其他来源代替。

内部诊断保存路由目标、每路最佳原始证据、旧池与池外候选数、真正送审的池外数量；可以定位“召回了却没有送审”的问题。资料卡新增 80% 完整率规则独立于排序，不作推荐资格门槛。

## 用户可见内容与限制

资料概览按整个已整理范围展示三项：可选题目（基础池及池外题目）、可检索题面（含本地归档与公开缓存）、AI 资料卡（当前范围内用户已收录资料卡的题目数，并非全部题目已分析）。统计在 `GET /api/intelligent/pool` 的 `overview` 返回。条件变化时标明旧范围；归档不可读时仅统计仍可读取的缓存题面，并提示限制。

100 题基础池、基础池内题面/题解/代码数量、完整率规则、题目表格和维护按钮默认折叠。推荐完成后自动刷新概览，也可手动刷新统计；刷新不调用模型。基础池容量不再表现为总检索上限。

推荐页仅显示题号、名称、Rating、原题链接和固定的无剧透训练方向说明。标签、具体算法、学习卡、审查推理都留在内部；题解及参考代码须在资料窗口主动展开。推荐理由采用受控枚举转文案，避免自由生成内容泄漏解法。

材料限长时显式标注截断；参考代码只用第一份公开实现，不把它认定为完整 AC，不执行代码。PDF 文字提取可能丢失公式，保留来源与限制。资料获取失败留缓存并暂缓，禁止把错误页当正文。模型可能误解题意或训练价值，顺序稳定性也未被证明；保存快照解决刷新变动，不意味着推荐是最优解。

## 验证

离线测试覆盖独立规则、新增卡 80% 配额、标签逻辑、池外正文召回、无资料但可推荐、冷启动、共享缓存、取消、账号隔离、输入变更不发布及结果复用。`test_smart_retrieval.py` 使用确定性的合成向量检查新旧题公平排序、重复卡片不加分、题面请求不误用题解、元数据可推荐及取消，不将其当作真实模型质量测试。开发用例独立于用户验证请求；真实输入、输出、代码版本、资料哈希和结果保留在忽略的 `.local` 文件中。

`test_smart_statement.py` 覆盖全范围语义召回（关键词零命中也能进入候选）、长题面尾部证据、中文原文位置、分块重叠、向量断点复用、无匹配时两批审查、跳过题解抓取，以及未审查题的资料变化导致旧结果过期。合成编码器只验证流程；真实效果另用正式服务和独立数据库实验。
